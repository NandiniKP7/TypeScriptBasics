# Readonly Collections

## What Problem Does This Solve?

Suppose another part of the program gives your function a list of prices:

```ts
const prices = [10, 20, 30];
```

Your function needs to:

- read the prices
- calculate a total
- find certain prices
- create new results

But it should **not accidentally change the original list**.

That is where a readonly collection is useful.

```text
Original data
[10, 20, 30]
      ↓
read / calculate / filter / transform
      ↓
new result
      ↓
original data stays [10, 20, 30]
```

The important idea is:

> `readonly` does not mean "you cannot do anything with the array."

It means:

```text
READ original data             ✅
PROCESS original data          ✅
CALCULATE from it              ✅
CREATE new results             ✅

CHANGE the original collection ❌
```

---

## 1. Normal Array vs Readonly Array

A normal array allows both reading and changing:

```ts
const prices: number[] = [10, 20, 30];

console.log(prices[0]); // ✅ read

prices.push(40);        // ✅ change
prices[0] = 100;        // ✅ change
```

A readonly array allows you to work with the data but prevents changing the original collection:

```ts
const prices: readonly number[] = [10, 20, 30];

console.log(prices[0]); // ✅ read
```

You can calculate:

```ts
let total = 0;

for (let i = 0; i < prices.length; i++) {
    total += prices[i];
}

console.log(total); // 60
```

You can create a new filtered array:

```ts
const expensivePrices = prices.filter(
    price => price > 15
);
```

Result:

```text
expensivePrices → [20, 30]
```

You can create a new transformed array:

```ts
const doubledPrices = prices.map(
    price => price * 2
);
```

Result:

```text
doubledPrices → [20, 40, 60]
```

And the original remains:

```text
prices → [10, 20, 30]
```

That is the main purpose of readonly collections.

---

## 2. Basic Syntax

Normal number array:

```ts
number[]
```

Readonly number array:

```ts
readonly number[]
```

Example:

```ts
const scores: readonly number[] = [
    90,
    85,
    95
];
```

For strings:

```ts
const names: readonly string[] = [
    "Nina",
    "Maya"
];
```

Mental model:

```text
number[]
   ↓
READ + CHANGE


readonly number[]
        ↓
READ + PROCESS
        ↓
original stays protected
```

## 3. What Can I Do With a Readonly Array?

### Read individual values

```ts
const scores: readonly number[] = [
    90,
    85,
    95
];

console.log(scores[0]);
```

### Check its length

```ts
console.log(scores.length);
```

### Loop through it

```ts
for (let i = 0; i < scores.length; i++) {
    console.log(scores[i]);
}
```

### Calculate from it

```ts
let total = 0;

for (let i = 0; i < scores.length; i++) {
    total += scores[i];
}
```

### Filter into a new array

```ts
const highScores = scores.filter(
    score => score >= 90
);
```

### Transform into a new array

```ts
const bonusScores = scores.map(
    score => score + 5
);
```

The important pattern is:

```text
readonly collection
       ↓
      read
       ↓
    process
       ↓
new value / new collection
```

---

## 4. What Does Readonly Prevent?

It prevents operations that mutate the original array.

```ts
const scores: readonly number[] = [
    90,
    85,
    95
];
```

These are rejected:

```ts
scores.push(100);    // ❌
scores.pop();        // ❌
scores[0] = 100;     // ❌
```

Why?

Because each one tries to change `scores` itself.

Compare:

```ts
const bonusScores = scores.map(
    score => score + 5
);
```

This is allowed because `map()` creates a **new array**.

```text
scores
[90, 85, 95]
      ↓ map()
bonusScores
[95, 90, 100]

scores is still
[90, 85, 95]
```

## 5. Why Is This Useful in Functions?

This is one of the most useful reasons to use readonly collections.

Suppose we have:

```ts
const prices = [10, 20, 30];
```

We give those prices to a function:

```ts
calculateTotal(prices);
```

The function only needs to calculate a total.

It does not need permission to change the original array.

So we can write:

```ts
function calculateTotal(
    prices: readonly number[]
): number {

    let total = 0;

    for (let i = 0; i < prices.length; i++) {
        total += prices[i];
    }

    return total;
}
```

Now the function can:

```text
read prices       ✅
loop over prices  ✅
calculate total   ✅
```

but it cannot accidentally do:

```ts
prices.push(100); // ❌
prices[0] = 500;  // ❌
```

Think of the parameter as saying:

> "Give me this collection so I can use its data, but this function should not modify the original collection."

## 6. `ReadonlyArray<T>`

TypeScript gives us two ways to write a readonly array.

This:

```ts
readonly number[]
```

and this:

```ts
ReadonlyArray<number>
```

mean the same basic thing.

Example:

```ts
const prices1: readonly number[] = [
    10,
    20,
    30
];

const prices2: ReadonlyArray<number> = [
    10,
    20,
    30
];
```

For strings:

```ts
readonly string[]
```

is equivalent to:

```ts
ReadonlyArray<string>
```

Memory rule:

```text
readonly number[]
        =
ReadonlyArray<number>
```

They are two syntax styles for the same concept.

## 7. Readonly Collection of Objects

Readonly collections can contain objects too.

```ts
interface Product {
    name: string;
    price: number;
}

const products: readonly Product[] = [
    {
        name: "Keyboard",
        price: 50
    },
    {
        name: "Mouse",
        price: 25
    }
];
```

We can read and process the products:

```ts
for (let i = 0; i < products.length; i++) {
    console.log(products[i].name);
}
```

We can create a new result:

```ts
const expensiveProducts = products.filter(
    product => product.price > 30
);
```

Result:

```text
expensiveProducts
      ↓
Keyboard
```

The original `products` array stays unchanged.

---

## 8. Important: What Exactly Is Readonly?

Look at:

```ts
const products: readonly Product[] = [
    {
        name: "Keyboard",
        price: 50
    }
];
```

Here, the **collection** is readonly.

So this is blocked:

```ts
products.push({
    name: "Mouse",
    price: 25
}); // ❌
```

And replacing an array position is blocked:

```ts
products[0] = {
    name: "Laptop",
    price: 900
}; // ❌
```

But look at the `Product` interface:

```ts
interface Product {
    name: string;
    price: number;
}
```

Its properties are not readonly.

Therefore:

```ts
products[0].price = 60; // ✅
```

is still allowed.

Why?

```text
readonly Product[]
        ↓
protects the collection

Product.price
        ↓
not readonly
```

If the product properties should also be protected:

```ts
interface Product {
    readonly name: string;
    readonly price: number;
}
```

Now:

```ts
products[0].price = 60; // ❌
```

So remember:

```text
readonly collection
≠
everything inside automatically becomes readonly
```

---

## 9. `const` vs `readonly`

These are different.

```ts
const scores: number[] = [
    80,
    90,
    100
];
```

Because of `const`, you cannot replace the entire array:

```ts
scores = [50, 60]; // ❌
```

But you can still change the existing array:

```ts
scores.push(95); // ✅
scores[0] = 50;  // ✅
```

Now:

```ts
const scores: readonly number[] = [
    80,
    90,
    100
];
```

The readonly type also prevents mutation:

```ts
scores.push(95); // ❌
scores[0] = 50;  // ❌
```

Mental model:

```text
const
  ↓
"this variable cannot point to a different array"


readonly array
  ↓
"this array should not be mutated through this reference"
```

# Complete Example

Suppose a shopping cart already contains prices:

```ts
const cartPrices = [
    25,
    40,
    15,
    60
];
```

We want a function that:

- reads the prices
- calculates the total
- does not modify the original cart

```ts
function calculateCartTotal(
    prices: readonly number[]
): number {

    let total = 0;

    for (let i = 0; i < prices.length; i++) {
        total += prices[i];
    }

    return total;
}

const total = calculateCartTotal(cartPrices);

console.log(total);
```

Result:

```text
cartPrices
[25, 40, 15, 60]
        ↓
calculateCartTotal()
        ↓
25 + 40 + 15 + 60
        ↓
140
```

After the function runs:

```text
cartPrices
[25, 40, 15, 60]
```

The original collection is unchanged.

That is the purpose of the readonly parameter.

# Memory Rule

Do not think:

```text
readonly = I cannot do anything
```

Think:

```text
readonly = I can USE the data
           without CHANGING the original
```

The flow is:

```text
READ
  ↓
PROCESS
  ↓
CREATE RESULT
  ↓
ORIGINAL STAYS UNCHANGED
```

And remember:

```text
const
→ protects the variable assignment

readonly array
→ protects the collection from mutation

readonly object properties
→ protect those individual properties
```
